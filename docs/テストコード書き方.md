## テストの基本

### テストの種類

種類 | 対象 | 速度 | 備考
--- | --- | --- | ---
単体テスト(Unit) | 関数・クラス単体 | 速い | 外部依存はモックに置き換える。CIで毎回実行する
結合テスト(Integration) | 複数モジュールの連携 | 中 | 実ファイル・通信などを含む場合がある
システムテスト(E2E) | システム全体 | 遅い | 実機や実環境が必要な場合が多い

本資料では主に**単体テスト**を扱う。

### 良いテストの条件

- **独立している**: 他のテストの実行順序・結果に依存しない
- **再現性がある**: 何度実行しても同じ結果になる(時刻・乱数・ネットワークに依存しない)
- **高速**: 数ミリ秒〜数百ミリ秒で終わる
- **1テスト1観点**: 失敗したときに原因が特定しやすい
- **仕様が読み取れる**: テスト名とコードだけで期待動作が分かる

### AAAパターン
テストは `Arrange`(準備) → `Act`(実行) → `Assert`(検証)の3段階で書く。

```python
def test_add():
    # Arrange
    a, b = 1, 2
    # Act
    result = add(a, b)
    # Assert
    assert result == 3
```

### テスト名の付け方
「何を」「どういう条件で」「どうなるか」が分かる名前にする。

- Python: `test_<対象>_<条件>_<期待結果>` 例: `test_divide_by_zero_raises_error`
- C++: `TEST(<対象>, <条件_期待結果>)` 例: `TEST(Calc, DivideByZero_Throws)`

## pytest(Python)

### インストールと実行
```console
$ pip install pytest pytest-cov
$ pytest                      # 全テスト実行(import の設定は「ディレクトリ構成」を参照)
$ python -m pytest            # カレントディレクトリを import パスに追加して実行
$ pytest tests/test_calc.py   # ファイル指定
$ pytest -k "add"             # 名前でフィルタ
$ pytest -v                   # 詳細表示
$ pytest -x                   # 最初の失敗で停止
$ pytest --cov=src            # カバレッジ測定
```

- ファイル名は `test_*.py` または `*_test.py`
- 関数名は `test_` で始める(クラスの場合は `Test` で始める)

### 基本的なテスト
テスト対象:
```python
# src/calc.py
def add(a, b):
    return a + b

def divide(a, b):
    if b == 0:
        raise ValueError("division by zero")
    return a / b
```

テストコード:
```python
# tests/test_calc.py
import pytest

from src.calc import add, divide

def test_add():
    assert add(1, 2) == 3

def test_divide():
    assert divide(6, 3) == 2

def test_divide_float():
    assert divide(1, 3) == pytest.approx(0.3333, rel=1e-3)  # 浮動小数点は approx
```

`assert` だけでよく、失敗時は pytest が値の差分を自動で表示する。

### アサーションの種類(pytest)

pytestで使う検証方法を以下に示す。基本は素の `assert` で、特殊な比較のみ専用の関数を使う。

- `assert` は失敗した時点でそのテストを**中断**する
- 失敗しても続行したい場合は、プラグイン `pytest-check` を使う

書き方 | 内容
--- | ---
`assert a == b` / `assert a != b` | 等しい / 等しくない
`assert a < b` / `<=` / `>` / `>=` | 大小比較
`assert x` / `assert not x` | 真偽
`assert x is None` / `assert x is not None` | `None` 判定
`assert a == pytest.approx(b, abs=eps)` | 許容誤差(絶対)
`assert a == pytest.approx(b)` | 浮動小数点(デフォルトは相対誤差 1e-6)
`assert s1 == s2` | 文字列の比較
`assert a == b` / `assert x in list` | リスト・辞書なども `==` でそのまま比較可
`assert isinstance(x, T)` | 型の確認
`with pytest.raises(ex):` | 指定した例外が投げられる
`with pytest.raises(ex, match="regex"):` | 例外メッセージも正規表現で検証
`stmt` をそのまま書く | 例外が出れば自動的にテスト失敗
`with pytest.warns(W):` | 警告が出る
`pytest.fail("理由")` | 明示的に失敗させる
`pytest.skip("理由")` / `@pytest.mark.skipif(cond, reason="...")` | スキップ
`@pytest.mark.skip` | テストを無効化
`@pytest.mark.xfail` | 既知の不具合(失敗しても全体は成功扱い)
`with pytest.raises(SystemExit):` / `subprocess` | プロセス終了の検証
`m.f.assert_called_once_with(x)` | モックの呼び出し検証
`assert cond, "msg"` | 失敗時の追加メッセージ

numpy配列の比較には `numpy.testing.assert_allclose(a, b, rtol=1e-6)` を使う(`assert a == b` は配列では使えない)。

```python
import numpy as np
import pytest

from src.calc import add, divide

def test_assertions():
    assert add(1, 2) == 3
    assert 0.1 + 0.2 == pytest.approx(0.3)
    assert "ok" in ["ok", "ng"]
    x = 2
    result = divide(1, x)
    assert result is not None, f"result is None (input={x})"
    np.testing.assert_allclose(np.array([1.0, 2.0]), np.array([1.0, 2.0000001]))
```

### 例外のテスト
```python
import pytest

def test_divide_by_zero_raises_error():
    with pytest.raises(ValueError, match="division by zero"):
        divide(1, 0)
```

### パラメータ化
入力と期待値の組を並べて、同じテストを複数ケースで実行する。
```python
import pytest

@pytest.mark.parametrize("a, b, expected", [
    (1, 2, 3),
    (0, 0, 0),
    (-1, 1, 0),
])
def test_add_param(a, b, expected):
    assert add(a, b) == expected
```

### フィクスチャ
テストの前処理・後処理を共通化する。
```python
import pytest

@pytest.fixture
def sample_file(tmp_path):          # tmp_path は pytest 組み込み(一時ディレクトリ)
    p = tmp_path / "data.txt"
    p.write_text("hello")
    return p

def test_read(sample_file):
    assert sample_file.read_text() == "hello"
```

- `yield` を使うと後処理を書ける
- `conftest.py` に書くと、同じディレクトリ以下の全テストで共有できる
- `scope="module"` / `"session"` で生成回数を減らせる(ただし独立性に注意)

```python
@pytest.fixture
def connection():
    conn = open_connection()
    yield conn          # テスト実行
    conn.close()        # 後処理
```

### モック
外部依存(ファイル、通信、ハードウェアなど)を置き換える。標準の `unittest.mock` か `pytest-mock` を使う。
```python
from unittest.mock import patch, MagicMock

def test_fetch_uses_client():
    client = MagicMock()
    client.get.return_value = {"status": "ok"}

    result = fetch_status(client)

    assert result == "ok"
    client.get.assert_called_once_with("/status")

# src/module.py で `from time import time` として使っている場合
def test_with_patch():
    with patch("src.module.time", return_value=1000.0):
        assert get_timestamp() == 1000.0
```

- `patch` の対象は「**使われている側**のモジュール名」で指定する
  - `src/module.py` が `from time import time` の場合: `patch("src.module.time")`(`patch("time.time")` では置き換わらない)
  - `src/module.py` が `import time` の場合: `patch("src.module.time.time")`。これは `time` モジュール自体の関数を置き換えるので、`patch("time.time")` と同じく**プログラム全体**に影響する

```text
project/
├── src/
│   └── calc.py
├── tests/
```

### 基本的なテスト
テスト対象:
```cpp
// src/calc.h
#pragma once
#include <stdexcept>

inline int add(int a, int b) { return a + b; }

inline double divide(double a, double b) {
    if (b == 0) throw std::invalid_argument("division by zero");
    return a / b;
}
```

テストコード:
```cpp
// tests/calc_test.cpp
#include <gtest/gtest.h>
#include "calc.h"

TEST(Calc, Add) {
    EXPECT_EQ(add(1, 2), 3);
}

TEST(Calc, DivideFloat) {
    EXPECT_NEAR(divide(1.0, 3.0), 0.3333, 1e-3);   // 浮動小数点は NEAR
}

TEST(Calc, DivideByZero_Throws) {
    EXPECT_THROW(divide(1.0, 0.0), std::invalid_argument);
}
```

`GTest::gtest_main` をリンクすれば `main()` は不要。

### アサーションの種類

- `EXPECT_*`: 失敗しても**テストを続行**する
- `ASSERT_*`: 失敗したら**そのテストを中断**する(後続が前提に依存する場合に使う)

マクロ | 内容
--- | ---
`EXPECT_EQ(a, b)` / `EXPECT_NE(a, b)` | 等しい / 等しくない
`EXPECT_LT` / `LE` / `GT` / `GE` | `<` / `<=` / `>` / `>=`
`EXPECT_TRUE(x)` / `EXPECT_FALSE(x)` | 真偽
`EXPECT_FLOAT_EQ` / `EXPECT_DOUBLE_EQ` | 浮動小数点(ULPベースで比較)
`EXPECT_NEAR(a, b, eps)` | 許容誤差つき比較
`EXPECT_STREQ(s1, s2)` | C文字列の比較(`std::string` は `EXPECT_EQ` でよい)
`EXPECT_THROW(stmt, ex)` | 指定した例外が投げられる
`EXPECT_NO_THROW(stmt)` / `EXPECT_ANY_THROW(stmt)` | 例外なし / 何かしらの例外
`EXPECT_DEATH(stmt, regex)` | プロセスが異常終了する

失敗時の追加メッセージ: `EXPECT_EQ(a, b) << "detail: " << x;`

### テストフィクスチャ
複数テストで共通の前処理・後処理を使う場合は `TEST_F` を使う。
```cpp
#include <stack>

class StackTest : public ::testing::Test {
protected:
    void SetUp() override {          // 各テストの前に実行
        stack.push(1);
        stack.push(2);
    }
    void TearDown() override {}      // 各テストの後に実行

    std::stack<int> stack;
};

TEST_F(StackTest, TopIsLastPushed) {
    EXPECT_EQ(stack.top(), 2);
}

TEST_F(StackTest, PopReducesSize) {
    stack.pop();
    EXPECT_EQ(stack.size(), 1u);
}
```

テストごとにフィクスチャのインスタンスが新規生成されるため、テスト間で状態は共有されない。

### パラメータ化テスト
```cpp
class AddTest : public ::testing::TestWithParam<std::tuple<int, int, int>> {};

TEST_P(AddTest, Works) {
    auto [a, b, expected] = GetParam();
    EXPECT_EQ(add(a, b), expected);
}

INSTANTIATE_TEST_SUITE_P(
    Cases, AddTest,
    ::testing::Values(
        std::make_tuple(1, 2, 3),
        std::make_tuple(0, 0, 0),
        std::make_tuple(-1, 1, 0)));
```

### モック(GoogleMock)
インターフェース(純粋仮想クラス)を切り、依存をモックに差し替える。
```cpp
#include <gmock/gmock.h>

class IClient {
public:
    virtual ~IClient() = default;
    virtual std::string get(const std::string& path) = 0;
};

class MockClient : public IClient {
public:
    MOCK_METHOD(std::string, get, (const std::string& path), (override));
};

std::string fetch_status(IClient& c) { return c.get("/status"); }

TEST(Fetch, UsesClient) {
    MockClient client;
    EXPECT_CALL(client, get("/status"))
        .Times(1)
        .WillOnce(::testing::Return("ok"));

    EXPECT_EQ(fetch_status(client), "ok");
}
```

- テスト対象が具象クラスに直接依存していると差し替えられない。コンストラクタ等で**依存を外から注入**できる設計にする

## ROS2でのテスト
ROS2でも、テスト自体は `GTest`(C++)・`pytest`(Python)で書く。ビルドシステム(`ament`)に登録し、`colcon test` で実行する点が異なる。

### 基本の流れ

1. `package.xml` にテスト用の依存(`test_depend`)を書く
2. C++(`ament_cmake`)は `CMakeLists.txt` にテストを登録する。Python(`ament_python`)は登録不要で、pytest が `test_*.py` を自動で探す
3. `test/` ディレクトリにテストコードを置く
4. `colcon build` → `colcon test` で実行する

テストに使うツール:

種類 | ツール | 用途
--- | --- | ---
単体テスト(C++) | `ament_cmake_gtest` | ロジック、ノードクラス単体
単体テスト(Python) | `ament_cmake_pytest` / `pytest` | ロジック、ノードクラス単体

**ロジックはROSに依存しないクラス/関数に切り出す**と、`rclcpp::init` なしで通常の単体テストが書けて速く安定する。

### C++パッケージ(ament_cmake + GTest)

`package.xml`:
```xml
<test_depend>ament_cmake_gtest</test_depend>
```

`CMakeLists.txt`:
```cmake
if(BUILD_TESTING)
  find_package(ament_cmake_gtest REQUIRED)

  ament_add_gtest(${PROJECT_NAME}_test test/test_calc.cpp)
  target_link_libraries(${PROJECT_NAME}_test ${PROJECT_NAME}_lib)
  # ROS の依存が必要な場合
  # target_link_libraries(${PROJECT_NAME}_test rclcpp::rclcpp ${std_msgs_TARGETS})
  # (ament_target_dependencies も Jazzy では使えるが、新しいディストリビューションでは非推奨)
endif()
```

- `ament_add_gtest` は `gtest_main` を自動でリンクするため、`main()` は不要
- テスト対象は `add_library` でライブラリ化しておき、テストと本体の両方からリンクする

`rclcpp` を使うテスト(`rclcpp::init` が必要な場合):
```cpp
#include <gtest/gtest.h>
#include <rclcpp/rclcpp.hpp>
#include <std_msgs/msg/string.hpp>

class NodeTest : public ::testing::Test {
protected:
    static void SetUpTestSuite()    { rclcpp::init(0, nullptr); }
    static void TearDownTestSuite() { rclcpp::shutdown(); }
};

TEST_F(NodeTest, PublishesMessage) {
    auto node = std::make_shared<rclcpp::Node>("test_node");

    std_msgs::msg::String::SharedPtr received;
    auto sub = node->create_subscription<std_msgs::msg::String>(
        "topic", 10, [&](std_msgs::msg::String::SharedPtr msg) { received = msg; });
    auto pub = node->create_publisher<std_msgs::msg::String>("topic", 10);

    // 購読側と接続されるまで最大1秒待つ(接続前に publish するとメッセージが届かないことがある)
    auto start = node->now();
    while (pub->get_subscription_count() == 0 && (node->now() - start).seconds() < 1.0) {
        rclcpp::spin_some(node);
    }
    ASSERT_GT(pub->get_subscription_count(), 0u);

    std_msgs::msg::String msg;
    msg.data = "hello";
    pub->publish(msg);

    // コールバックが呼ばれるまで最大1秒待つ(sleepで待たない)
    start = node->now();
    while (!received && (node->now() - start).seconds() < 1.0) {
        rclcpp::spin_some(node);
    }

    ASSERT_NE(received, nullptr);
    EXPECT_EQ(received->data, "hello");
}
```

### Pythonパッケージ(ament_python + pytest)

`package.xml`:
```xml
<test_depend>python3-pytest</test_depend>
```

`setup.py`(Jazzy の `ros2 pkg create` が生成する形。`tests_require` は setuptools で非推奨):
```python
extras_require={
    'test': [
        'pytest',
    ],
},
```

テストは `test/` 配下に `test_*.py` として置けばよい(`setup.py` への登録は不要)。

```python
# test/test_node.py
import pytest
import rclpy
from std_msgs.msg import String

@pytest.fixture(scope="module")
def rclpy_init():
    rclpy.init()
    yield
    rclpy.shutdown()

def test_publish_and_receive(rclpy_init):
    node = rclpy.create_node("test_node")
    received = []
    node.create_subscription(String, "topic", lambda m: received.append(m), 10)
    pub = node.create_publisher(String, "topic", 10)

    # 購読側と接続されるまで最大 約1秒待つ(接続前に publish するとメッセージが届かないことがある)
    for _ in range(10):
        if pub.get_subscription_count() > 0:
            break
        rclpy.spin_once(node, timeout_sec=0.1)
    assert pub.get_subscription_count() > 0

    pub.publish(String(data="hello"))
    for _ in range(10):                       # 最大 約1秒待つ
        rclpy.spin_once(node, timeout_sec=0.1)
        if received:
            break

    assert received and received[0].data == "hello"
    node.destroy_node()
```

`ament_cmake` のパッケージでPythonテストを書く場合は、`package.xml` に依存を追加し、`CMakeLists.txt` に登録する。
```xml
<test_depend>ament_cmake_pytest</test_depend>
```
```cmake
find_package(ament_cmake_pytest REQUIRED)
ament_add_pytest_test(test_calc test/test_calc.py)
```

### 実行方法(colcon test)
```console
$ colcon build --packages-select <pkg>
$ source install/setup.bash
$ colcon test --packages-select <pkg>                       # 実行
$ colcon test-result --verbose                              # 結果の一覧(失敗箇所)
$ colcon test --packages-select <pkg> --event-handlers console_direct+   # ログをその場で表示
```

オプション | 説明
--- | ---
`--ctest-args -R <名前>` | CMake登録のテスト(GTest)を名前で絞り込む
`--pytest-args -k <名前>` | pytestを名前で絞り込む
`--retest-until-pass 3` | 失敗したテストを最大3回再実行(不安定なテストの確認用)
`--packages-select <pkg>` | 対象パッケージを指定

GTestのバイナリを直接実行することもできる。
```console
$ ./build/<pkg>/<pkg>_test --gtest_filter=Calc.*
```

注意点:
- ノードを起動するテストは、同じネットワーク上の他のROS2プロセスと干渉することがある。`ROS_DOMAIN_ID` を変えるか、`ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST` を設定する(`ROS_LOCALHOST_ONLY=1` は Jazzy で非推奨)。C++では、`ament_cmake_ros` の `ament_add_ros_isolated_gtest`(`ament_add_gtest` の代わりに使う)でテストごとにドメインIDを自動分離できる
- `sleep` で待たず、条件が満たされるまで `spin_once` / `spin_some` でタイムアウト付きのループにする
- パッケージを修正したら、`colcon build` をやり直してから `colcon test` を実行する(ビルドしないと古いコードをテストする)

## GTestとpytestの対応表

やりたいこと | pytest (Python) | GTest (C++)
--- | --- | ---
等価比較 | `assert a == b` | `EXPECT_EQ(a, b)`
浮動小数点比較 | `pytest.approx` | `EXPECT_NEAR` / `EXPECT_DOUBLE_EQ`
例外 | `pytest.raises(E)` | `EXPECT_THROW(stmt, E)`
前処理・後処理 | `@pytest.fixture` | `SetUp` / `TearDown` (`TEST_F`)
パラメータ化 | `@pytest.mark.parametrize` | `TEST_P` + `INSTANTIATE_TEST_SUITE_P`
モック | `unittest.mock` | GoogleMock (`MOCK_METHOD`)
フィルタ実行 | `pytest -k "name"` | `--gtest_filter=Suite.Name`
カバレッジ | `pytest --cov` | `gcov` / `lcov`(`--coverage` ビルド)

## テスト作成時の注意点

- **正常系だけでなく境界値・異常系も書く**(0、負数、空、最大値、`None`/`nullptr`、例外)
- **実装の内部ではなく振る舞いを検証する**(内部実装に依存すると、リファクタで壊れる)
- **テスト内にロジック(if/for)を書かない**。期待値は直接書く
- **時刻・乱数・ファイル・通信は注入またはモックで固定する**
- **バグ修正時は、まず再現するテストを書いてから直す**
- **CIで自動実行する**(`GitHub Actions` での実行方法は[CIのワークフロー定義](../.github/workflows/ci.yml)と[README](../README.md)を参照)
